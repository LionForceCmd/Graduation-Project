# Система знаний команды

Выпускной проект, вариант E. Сервис хранит документы команды, по вопросу находит нужные абзацы и отвечает **только на их основе**, приложив цитаты. Если подходящих фрагментов нет или уверенность низкая, он честно отвечает «данных недостаточно» и ставит `needs_review=true`. Каждый запуск записывается в журнал аудита.

```
веб-панель → API (FastAPI) → SQLite ──► поиск (BM25 + покрытие слов) ─► ИИ-операция (строгий JSON)
                                                                              │ mock или Ollama
                                      audit_runs ◄── контроль качества: схема, цитаты, needs_review
```

## Два режима

| | `mock` (по умолчанию) | `ollama` |
|---|---|---|
| Языковая модель | не нужна | локальная, через Ollama |
| Интернет | не нужен | не нужен |
| Как формируется ответ | из самых подходящих предложений найденных абзацев | модель пишет ответ по найденным абзацам и возвращает JSON |
| Скорость | мгновенно | секунды (зависит от модели и железа) |
| Подходит для | быстрого запуска на любом компьютере, проверки | демо-видео, более «живые» ответы |

Контроль качества **одинаков в обоих режимах** и от модели не зависит:

- структура JSON проверяется схемой (`pydantic`): иначе `SCHEMA_MISMATCH` или `INVALID_JSON`;
- каждая цитата должна **дословно** присутствовать в найденном тексте, выдуманные цитаты отбрасываются;
- нет проверенных источников → `needs_review=true`, причина `NO_SOURCES`, модель про это не «додумывает»;
- `confidence="low"` → `needs_review=true`, причина `LOW_CONFIDENCE`;
- Ollama недоступна → сервис не падает, а отвечает режимом mock, причина пишется в аудит (`LLM_UNAVAILABLE`).

## Запуск за 5 минут

Нужен **Python 3.10+** (или Docker). Папку проекта откройте в терминале.

### Вариант 1. Без Ollama

Windows: двойной щелчок по `run_mock.bat` (первый раз создаст `.venv` и поставит зависимости) или вручную:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --port 4000
```

Linux/macOS: `./run.sh`

Docker: `docker compose up --build`

### Вариант 2. С Ollama

1. Установите [Ollama](https://ollama.com), скачайте модель: `ollama pull qwen3.5` (проверьте: `ollama list`).
2. Запустите `run_ollama.bat` (Linux/macOS: `./run.sh ollama`). Другая модель: `set OLLAMA_MODEL=deepseek-coder-v2:16b` перед запуском.
3. Docker: `$env:LLM_PROVIDER="ollama"; docker compose up --build`. Контейнер обращается к Ollama на вашем компьютере через `host.docker.internal`.

Скорость в режиме Ollama зависит от железа: на ноутбуке с `qwen3.5` (6,6 ГБ, частично на CPU) ответ занимает около 10–15 секунд, а первый запрос ещё и загружает модель в память. Если Ollama зависла или недоступна, сервис отвечает режимом mock, а причина попадает в аудит (`LLM_UNAVAILABLE`).

Откройте **http://localhost:4000**. Вверху панели видно текущий режим (для Ollama ещё и статус модели). Swagger с описанием всех точек доступа: http://localhost:4000/docs

### Загрузить тестовые данные и проверить

В другом терминале (сервис должен работать):

```powershell
python scripts/eval.py
```

Скрипт загружает 5 документов из `tests_data/kb_documents.jsonl`, задаёт 10 вопросов из `tests_data/kb_questions.jsonl` и печатает таблицу «ожидалось → получилось → источники → причина». В конце печатает сводку по `audit_runs` (по каждому действию: сколько записей и с каким статусом, какие причины в поле `error`) — это доказательство, что аудит пишется. Код возврата 1, если хоть один ответ не совпал с ожиданием. Автотесты (без Ollama): `pip install pytest httpx` и `python -m pytest -q`.

## Переменные окружения

См. `.env.example` (скопируйте в `.env`; секретов в проекте нет).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `mock` | `mock` или `ollama` |
| `OLLAMA_URL` | `http://localhost:11434` | адрес Ollama |
| `OLLAMA_MODEL` | `qwen3.5:latest` | модель |
| `LLM_TEMPERATURE` | `0.1` | низкая температура: меньше «фантазий» |
| `LLM_TIMEOUT` | `180` | секунд на ответ модели |
| `DB_PATH` | `data/kb.sqlite3` | файл базы |
| `MIN_COVERAGE` | `0.45` | порог: доля слов вопроса, найденных во фрагменте |
| `SEARCH_TOP_K` | `3` | сколько фрагментов отдаём в ответ |

## Точки доступа (curl)

```bash
# 1. добавить документ
curl -X POST localhost:4000/kb/documents -H "Content-Type: application/json" \
  -d '{"title":"Правила","text":"## Созвон\nСтендап проходит в 10:30 по Москве."}'
# -> {"status":"ok","document_id":"doc_..."}

# 2. список документов (витрина)
curl localhost:4000/kb/documents

# 3. вопрос (ответ с источниками)
curl -X POST localhost:4000/kb/ask -H "Content-Type: application/json" \
  -d '{"question":"Во сколько стендап?"}'
# -> {"answer":"...","sources":[{"document_id":"doc_...","quote":"..."}],"needs_review":false,...}

# 4. ИИ-операция отдельно (строгий JSON из 4 полей)
curl -X POST localhost:4000/ai/answer_with_sources -H "Content-Type: application/json" \
  -d '{"question":"Во сколько стендап?","context":"Стендап проходит в 10:30 по Москве."}'
```

Служебные точки для панели: `GET /qa`, `GET /qa/{id}`, `GET /audit`, `GET /export/qa?format=json|csv`, `GET /export/audit?format=json|csv`, `GET /health`.

Ошибки: `422` при пустых или слишком длинных `title`, `text`, `question` (лимиты 200, 50 000 и 500 символов); `404` для неизвестного документа; `500` при внутренней ошибке. Во всех случаях в `audit_runs` появляется запись.

## База данных и аудит

Файл `data/kb.sqlite3` (в Docker это `./data` рядом с проектом). Таблицы: `documents`, `snippets` (абзацы документов), `qa_runs` (история вопросов), `audit_runs` (аудит всех команд: `action, input, output, status, error, duration_ms, created_at`).

Посмотреть данные: вкладка **Аудит** в панели (карточка с входом и выходом, фильтр «только ошибки», экспорт JSON/CSV) или

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/kb.sqlite3'); [print(r) for r in c.execute('select created_at, action, status, error from audit_runs order by created_at desc limit 20')]"
```

## Как воспроизвести «ручную проверку»

1. `python scripts/eval.py` (вопросы 8–10 заведомо без ответа в базе) или в панели на вкладке «Вопросы» спросите: **«Какая зарплата у директора студии?»**
2. Ответ: «Данных в базе знаний недостаточно…», метка «требует проверки», причина `NO_SOURCES` и подсказка, что делать.
3. Та же запись видна на вкладке «История» (фильтр «только требует проверки») и в «Аудите» в поле `error`.

## Тестовые данные (`tests_data/`)

Документы (`kb_documents.jsonl`, по 21–28 строк): правила работы команды, частые вопросы клиентов, шаблоны ответов, словарь терминов, процесс запуска задачи.

| № | Вопрос | needs_review | Почему | Опора |
|---|---|---|---|---|
| 1 | Во сколько проходит ежедневный созвон команды? | false | время стендапа указано явно | Правила работы команды |
| 2 | Сколько времени даётся на ревью задачи? | false | «в течение 1 рабочего дня» | Правила работы команды |
| 3 | Через сколько дней возвращаются деньги клиенту при отказе от услуги? | false | «в течение 7 рабочих дней» | Частые вопросы клиентов |
| 4 | Как клиенту сменить тариф поддержки? | false | личный кабинет, раздел «Подписка» | Частые вопросы клиентов |
| 5 | Что означает термин MVP? | false | есть определение | Словарь терминов |
| 6 | Что ответить клиенту, который просит перенести срок сдачи? | false | есть готовый шаблон | Шаблоны ответов |
| 7 | Какие бывают статусы задачи? | false | перечислены пять статусов | Процесс запуска задачи |
| 8 | Какая зарплата у директора студии? | **true** | в базе нет информации | — |
| 9 | Какой пароль от Wi-Fi в офисе? | **true** | такой информации нет | — |
| 10 | Как оформить командировку в Токио? | **true** | про командировки ничего нет (слово «команда» не должно давать ложного совпадения) | — |

Успех: для 1–7 есть источники из ожидаемого документа; для 8–10 источников нет, ответ «данных недостаточно», `needs_review=true`.

## Как устроен поиск и его ограничения

Документы режутся на абзацы (`snippets`). Слова вопроса и абзацев нормализуются (регистр, `ё→е`, отбрасывание окончаний, стоп-слова). Абзац подходит, если в нём найдено не менее 45 % «веса» слов вопроса (редкие слова весят больше). Лучшие подходящие абзацы ранжируются BM25.

Честные ограничения: поиск по словам, а не по смыслу: синонимы («зарплата» и «оклад») он не свяжет, а нормализация русских слов упрощена. Для базы в десятки документов этого достаточно; для большой базы стоит добавить эмбеддинги. Порог `MIN_COVERAGE` можно подстроить под свои документы.
